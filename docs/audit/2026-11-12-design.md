## Fix strongly recommended

### F1 The step finder pushes CTC 02 over its 10 s limit

- **Rework if left:** high
- **Effort:** M
- **Evidence:** `.claude/worktrees/s1-audit/docs/specs/steps-slots.md:67` "NIST CTC 02's analysis stays under its 10 s limit (7-9 s today; if over, stop)"
- **Case:** Measured on `nist_ctc_02_asme1_ap242-e2.stp`: main 6.7 to 7.2 s, with the patch 10.3 s twice, about 3.3 s more. Every flat face that is not a pocket now walks its edges, and a face with one wall and one open edge runs the enclosure rays and the reach test. The spec says to stop when this is over. The browser test on that file (`e2e/browser_engine.spec.ts`) was not run.
- **Fix:** Reject cheaply before any ray: return when no edge has a concave flat or round neighbour, and reuse the floor-pieces result the pocket pass already made. Time CTC 02 again before the next round.

### F2 Tilted floors (change 7) reverse a settled decision without asking

- **Rework if left:** high
- **Effort:** M
- **Evidence:** `.claude/worktrees/s1-audit/docs/DECISIONS.md:636` "steps and slots only on a floor along a part axis"
- **Case:** D-081 settled that steps sit only on a floor along a part axis, and the spec's Non-goals say the same. Round 1's change 7 keeps a tilted floor when one wall is on an axis, with no new decision (WS-07). A tilted step gets no direction unless it has one flat wall, so the access rule then flags it and the plan skips it. Class 9 and 10 faces are both in the target and outside the non-goal, which is the real question for Morgan.
- **Fix:** Ask Morgan whether MFCAD++ slanted steps (class 10) and V-floor steps (class 9) are in scope, given the target counts them. Until then, take change 7 out or record a proposed decision.

### F3 Side-reached steps (change 8) have no decision, and their depth and reach are measured the wrong way

- **Rework if left:** high
- **Effort:** M
- **Evidence:** `.claude/worktrees/s1-audit/web/src/engine/features/pockets.ts:1004` "o.side !== undefined ? [o.side]"
- **Case:** A floor with material over it is kept when a ray along an open-edge direction leaves the part, and the plan cuts it from that side. The spec says the reach test applies as for pockets and has no side-entry model. Depth is still measured along the floor normal, square to the cutter, so `step_depth` and the removal volume measure the wrong length. The reach ray starts in the floor's own plane, so it can graze the floor (unconfirmed). Round 1 also brought 5 and 2 closed-pocket faces (class 14) called steps, with no cause traced.
- **Fix:** Decide with Morgan whether side-cut notches are in scope. If they are, spec the direction, depth and reach rules and add a test part. If not, take change 8 out. Trace the class 14 calls either way.

### F4 Round 1 bought recall with wrong calls; the 0-wrong half of the target moved away

- **Rework if left:** high
- **Effort:** M
- **Evidence:** `.claude/worktrees/s1-audit/docs/research/steps-s1/README.md:27` "33 wrong (chamfer 16, class 6 6, class 14 5"
- **Case:** Wrong faces went from 21 to 33 on the first set and from 29 to 45 on the check set, while D-079 asks for 0. Chamfers are the largest group both times. Class 6 through-slot faces are called steps on both versions, which is the slot-against-step question S2 has to settle.
- **Fix:** Treat wrong faces as a gate in every round, beside recall. Fix the class 6 and class 14 calls before more recall work, and ask Morgan whether a chamfer face inside a step counts as wrong.

### F5 "A U-shaped class 22 is the same shape as a class 17 slot" is not shown by what was measured

- **Rework if left:** high
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/docs/research/steps-s1/README.md:31` "A U-shaped class 22 is the same shape as a class 17 slot"
- **Case:** The measurement counted instances by run shape only: 13 class 22 U shapes (79 faces) and 40 class 17 U shapes (164 faces). It did not compare the shapes themselves. The face counts differ (about 6.1 against 4.1 per instance). The page offered Morgan a D-019-style line on this claim, and that is a change to the D-079 target.
- **Fix:** Compare the 13 and the 40 by face types, wall count, open edges and proportions, and say how many are truly alike. Put the scoring choice to Morgan only after that.

### F6 The re-freeze guard is untested and lets any plan change through on a file that gains a step

- **Rework if left:** high
- **Effort:** M
- **Evidence:** `.claude/worktrees/s1-audit/web/src/engine/parity-refreeze.test.ts:32` "const PLAN_KEYS = ["setups", "operations", "tools", "tool_changes", "cost_drivers", "cost_total", "removal", "rows", "passed_rows"];"
- **Case:** On a file that gained a step, every one of these keys is set back to the old key before comparing. The only check left on holes and pockets is that each keeps its tools. A changed hole setup, cost or row would pass, and the frozen key then follows the engine. `masked`, `newIds`, `toolsOf` and `baseMasked` have no test, so nothing shows the guard refusing anything. It has not been run.
- **Fix:** Move the masking into a small module with a unit test: an allowed step change passes, and a changed hole feature, a lost hole tool, and a changed finding on a file with no step are each refused. Plant each bug once and see it fail.

## Other findings

### F7 `runs()` gives one run or two for the same wall, depending on where the wire starts

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/web/src/engine/features/pockets.ts:356` "const start = trace.findIndex((t) => t.kind !== "wall");"
- **Case:** Run directly: the trace wall A, cut, wall B, open (A and B one wall) gives two runs, while open, wall A, cut, wall B gives one. The walk can start on a cut, and the cut that closes the loop is never joined back. A step beside a pocket is then found or lost by edge order.
- **Fix:** Start at the first open edge, and join the last run to the first when the loop closes on a cut between pieces of one wall. Add a unit test for both orders.

### F8 A pocket's corners can be linked to a step

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/web/src/engine/features/pockets.ts:1031` "const byFace = new Map(pocketList.map((p) => [minOf(p.faces), p.id]));"
- **Case:** Pockets and steps now share one map keyed by their lowest face. If a step's lowest face equals a pocket's (a step's wall can be a pocket face), the step wins, and every corner of that pocket names the step. That changes pocket output (unconfirmed on a real part).
- **Fix:** Tag each corner with its owner's kind and key the map by kind and face.

### F9 Changes 1-8 have no DECISIONS entry, and the spec still states the old rules

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/docs/specs/steps-slots.md:16` "a step is symmetric: its wall, seen as a floor, has the floor as its wall"
- **Case:** The rule changes live only in the README. The spec's Terms still describe a symmetric step, runs split at every cut, and a slot-only subset drop. The README says the arc test replaces the facing-pair test for steps, but the code keeps both. J1 still says `em-0.188`. A fresh session would build on two disagreeing sources (SRC-01, SRC-04).
- **Fix:** Record the accepted changes as one proposed decision for Morgan. Then make the spec's Terms, J1 and Design match, and keep the README to measurements.

### F10 Each round's rules come from first-set misses, which weakens the check set as a held-out test

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/docs/research/steps-s1/README.md:21` "A trace of every missed step face (first set, version B: 384 faces in 154 instances)"
- **Case:** D-018 keeps the second set out of tuning. All causes so far came from the first set, so that rule held, but changes 2 and 6-8 were tuned and checked on first-set parts. The check set did rise (86.9% to 91.6%), so overfitting is not shown, but each round eats into it.
- **Fix:** Keep tracing causes on the first set only, and add an untouched third slice (`--skip 1000 --limit 500`) to report before Morgan is told a round passes.

### F11 The spec's open questions are stale

The UMD parts that disagree have not yet gone to Morgan with numbers, as the spec requires.

### F13 The target's PASS and FAIL lines have no test

- **Rework if left:** medium

- **Evidence:** `.claude/worktrees/s1-audit/web/src/grading/score.ts:361` "if (base) {"

### F14 The pass-or-flag check for `step_depth` judges no part

### F15 The re-freeze allow list differs from the spec, and the new set has no frozen key

### F16 Step findings show pocket wording or none

- **Rework if left:** low
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/web/src/engine/rules/access.ts:38` "const what = f.kind === "hole" ? "Hole" : "Pocket";"
- **Case:** A tilted step with no direction is reported as "Pocket opens … off the part's axes". `findings.ts` has no step line in `meta()`, so a deep-step finding shows no depth or tool. A step's corner says "pocket … deep". `turn_offaxis.ts` has the same Hole-or-Pocket wording.
- **Fix:** One kind-to-word map for hole, pocket and step, and a step branch in `meta()`.

### F17 Steps off the turning axis are measured but never judged

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/web/src/engine/rules/turn_offaxis.ts:10` "const KINDS = ["hole", "pocket"];"
- **Case:** On turned parts, `analyze.ts` now records the off-axis angle and offset for steps, and the lathe plan mills them. The rule that reads those numbers skips steps, so a flat off the turning axis gets no finding.
- **Fix:** Add steps to the rule's kinds (with F16's wording), or stop computing the numbers for steps, as the spec chooses.

### F18 The removal assumption still names only holes and pockets

- **Rework if left:** low
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/web/src/engine/removal.ts:10` "each hole's and pocket's own volume comes from its sizes (approximate)"
- **Case:** Steps' volumes are now counted, but the assumption shown to the user doesn't say so. Changing the text changes every milled key, so it needs the re-freeze to allow it.
- **Fix:** Say holes, pockets and steps, and allow that string in the re-freeze.

### F19 A step's `length` is not the floor edge the spec names

- **Rework if left:** low
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/web/src/engine/features/pockets.ts:1015` "dims_mm: { depth, length: maxOf(walls.map((w) => span(topo, w, n)))"
- **Case:** The spec says "along the longest wall's floor edge". The code takes the widest spread of any wall, which differs for round or filleted walls. A drawing would read the wrong length. No test asserts `length`.
- **Fix:** Measure the floor edge, or state the rule in the spec, and assert it on `st_through` and `st_l`.

### F20 Two J1 checks are weaker than the spec

- **Rework if left:** low
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/web/src/engine/port/steps_slots.test.ts:81` "if (s.floor === floorZ) expect(s.dims_mm.depth).toBeCloseTo(20, 6);"
- **Case:** `st_deep` checks depth only when the floor is the z face, so a wrong depth on the other floors passes. `st_l` checks that it has one direction, not that it is the floor's.
- **Fix:** Assert the expected depth and direction for whichever face is the floor, as `st_through` does.

### F21 Step dedupe can keep two copies or drop a real step

- **Rework if left:** low
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/web/src/engine/features/pockets.ts:992` "const kept = "
- **Case:** Unconfirmed on a real part. The same step seen from two floors whose face sets differ at equal size (a fillet on one side only) stays twice. A small step lying wholly inside a larger one's faces is dropped.
- **Fix:** Merge steps that share a floor-and-wall pair, and test it on a stair with fillets.

### F22 A tilted step that borrows its wall's direction passes access with numbers that disagree

- **Rework if left:** low
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/web/src/engine/rules/access.ts:54` "const angle = Math.min("
- **Case:** Unconfirmed. When a tilted floor takes its one wall's direction, the wall's vector is not added to `open_vectors`. The passed line then says it opens along that axis, but shows the tilted floor's angle. This follows from F2.
- **Fix:** Settle F2. If tilted steps stay, add the wall's vector when its direction is added.

### F23 The UMD tests rely on the default 5 s timeout, and share a list from a test file

- **Rework if left:** low
- **Effort:** S
- **Evidence:** `.claude/worktrees/s1-audit/web/src/engine/port/umd_counts.test.ts:31` "test(part, async () => {"
- **Case:** Each part takes about 0.2 to 0.9 s here. A slow CI runner could time one out and show a red that isn't a real failure. S2 is meant to reuse `PARTS` and `labelled`, and importing a test file registers its tests twice.
- **Fix:** Give the per-part tests an explicit timeout, and move `PARTS` and `labelled` to a kit module.
