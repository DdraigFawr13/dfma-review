Inventor parts research

2026-11-08 · for Morgan · can the app read Inventor .ipt parts and their features, and how do we test it

Yes, we can test it, and NIST gives us the parts. NIST publishes 16 Inventor part files (Inventor 2021 and 2024) of the same test parts we already use as STEP, in the public domain.

No free, open, Linux tool reads Inventor's hole features fully. Every .ipt holds the full shape (as an ACIS model) and its feature tree (Hole1, Extrusion1, Fillet1 …), but Autodesk doesn't document the format. The open-source reader (InventorLoader, GPL) gets hole sizes but not threads. The paid readers (HOOPS, CAD Exchanger, ODA) read the shape only, not features. Only Autodesk's own software reads everything, and that needs Inventor on Windows or Autodesk's cloud.

My suggestion, to decide in round 1: keep STEP for the shape, which already works. Add a small reader of our own that takes the feature data from the .ipt, which STEP loses (hole type, thread callout). Build it by comparing the 16 NIST .ipt files with their STEP twins. A second route is an Inventor add-in on the engineer's PC that exports STEP plus a feature list through Autodesk's API. That one only works if your company has Inventor seats.

1. NIST has Inventor files

The MBE PMI page lists, verbatim: "Autodesk Inventor [STC] Inventor 2024 [FTC/CTC] Inventor 2021". Our catalogue only had the hole test case zip, which has no Inventor file. I downloaded the zips and listed them myself:

Licence: the README in the zip says the test system "is not subject to copyright protection and is in the public domain" (17 U.S.C. 105). So we can commit them, as D-011 already allows for NIST files.

Two cautions. (a) The STC README says, of earlier versions, "the Inventor models were not" updated, then on 29 Aug 2023 "all of the Inventor models have been updated". So an Inventor STC part may differ a little from the CATIA/NX version the STEP came from. (b) NIST removed the authoring system from its STEP files ("Information that shows which CAD software generated the files has been removed"), so the STEP twins are not Inventor exports.

2. What's inside an .ipt

I opened all 16 NIST files with a 20-line script of my own. It uses olefile, a free BSD-licensed Python package, and ran in a scratch folder, not the app. What it found:

  • The file is a Microsoft compound file (the old Office container). Its data streams are zlib-compressed.
  • The shape is stored as ACIS binary (asmheader, version 226.0.3 in the 2021 files and 229.x in the 2024 files). ACIS is the kernel family Inventor's ShapeManager came from.
  • The feature tree is there by name. CTC 01 lists Hole1-7, Extrusion1-5, Fillet1-4, Chamfer1-2 and Rectangular Pattern1, plus "Hole Note" and "Feature Control Frame" annotations. The sizes and thread specs are in undocumented binary records.

3. Ways to read an .ipt

Prices are what each page said on 2026-11-08. "Features" means hole type, thread and counterbore, not only the shape.

A. Our own feature reader, with STEP for the shape suggested

Licence, cost
Ours. One small new dependency: olefile (BSD, free). Needs your OK (SAFE-01).
Inventor, Windows
Neither. Runs on Linux in our service.
Features
What we decode: names first, then hole parameters and the thread callout. The shape still comes from the STEP the engineer exports.
Lock-in
None.
Risks
The format is undocumented and may shift with Inventor releases (we saw ACIS 226 to 229 in 2021 to 2024). Autodesk's licence terms on reverse engineering: not checked. We'd write it ourselves without copying GPL code (see C).

B. Inventor add-in on the engineer's PC

Licence, cost
Uses the company's Inventor seats. No new spend if they exist.
Inventor, Windows
Both, on the PC only. The app server stays Linux.
Features
All of them, through Autodesk's API (the Hole features and their threads). The add-in writes STEP plus a feature list next to it.
Lock-in
Autodesk on the PC side only. Needs IT to allow an add-in.
Note
Apprentice, the free viewer API, gives "file references, assembly structure, B-Rep, geometry, render styles, and document properties" (Autodesk). Whether it gives hole features: not checked.

C. InventorLoader (open source, FreeCAD add-on)

Licence, cost
GPL-2.0, free. Linking it into our app would put the app under GPL terms. Running it as a separate converter keeps it at arm's length (inference, not legal advice).
Inventor, Windows
Neither, but needs FreeCAD (about 3 GB installed here).
Features
Reads hole type, diameter, depth and counterbore/countersink (I read its code: Create_FxHole). Threads not done (hole.Threaded = False; Create_FxThread unfinished).
Versions
"Only files from INVENTOR V2010 or newer are supported". One author, last change 2024-12-17.
Tested?
No. Running it on a NIST file here was blocked: the session won't run outside code without your say-so.

D. Autodesk cloud (APS)

Licence, cost
Design Automation for Inventor: 5 free hours a month, then "1 token or $3 for 12 minutes" ($15/h, my arithmetic). Model Derivative (.ipt to STEP): 60 free a month, then "$3 for 3 simple translations". Source: APS rate chart, 2025-11-12.
Inventor, Windows
Neither on our side. Needs an Autodesk account and API keys.
Features
Design Automation runs Inventor's API, so all of them (inference). Model Derivative gives STEP only.
Lock-in
Full Autodesk cloud. Company parts leave the building, which hits D-006.

E. Paid SDKs (shape only)

  • HOOPS Exchange: Inventor "Up to 2027 … B-rep Supported … PMI Unsupported". Feature trees only "With CATIA V5, Creo, NX and SolidWorks" (Tech Soft 3D, confirmed). Price: about $33,000/yr from a search snippet, not verified.
  • ODA MCAD SDK: "Inventor support in the SDK is currently read-only", needs "Sustaining membership or above". On the pricing page, membership starts at "$7,500 First Year Cost $4,500 Recurring Annual Cost", and the MCAD row reads "MCAD Converter for CATIA, Inventor … Under development N/A": no price for the Inventor part yet. No features mentioned.
  • CAD Exchanger SDK: Inventor shape and assemblies, Linux and Python. Price on quote. No features.
  • Spatial and Datakit also read Inventor shapes. Prices aren't public and no feature reading was found.

None of these reads features, and all are a large yearly cost. I don't suggest them.

4. How we'd test it

  • Pairs: 16 NIST parts as .ipt and STEP. Outside NIST, few pairs can be committed: AntoniWanot/BRICK has 7 (MIT, 3D-printed gearbox parts) and RatHeadFixation has 1 (CC0). GrabCAD, McMaster, TraceParts and MISUMI terms don't allow committing their files.
  • Through our own analysis: for each pair, run the app on the STEP, then on what the .ipt route gives. Compare holes found, diameters, depths, counterbores and threads. Check both against the NIST answer key (Report 3 Appendix A, the PMI spreadsheets), which says, for example, "F18-21 | Counterbored Holes - Set 1 | 4X Ø.415 ±.008".
  • Hole by hole: match each .ipt hole feature to a hole we find in the STEP by position and axis. The score is matched, missed and wrong, the same way D-018 scores recognition.
  • Threads are the real prize. The modelled diameter of a threaded hole differs between CAD systems (NIST Report 1, p28), so STEP shape alone can't name a thread. Inventor keeps the thread callout in the hole feature (inference from InventorLoader's code: threadDiam and thread fields).
  • Your own parts: pairs from your company's Inventor (exported STEP) would test the versions you actually use. The free Autodesk education licence can't be used: "'Educational Purposes' does not include commercial, professional or any other for-profit purposes."
